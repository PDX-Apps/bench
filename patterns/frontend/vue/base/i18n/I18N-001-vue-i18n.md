# i18n — vue-i18n (optional)

Internationalization with **vue-i18n** 9+. Common but **not universal** — only apply when the project has `vue-i18n` installed. A generated component must not hard-require i18n if the project doesn't use it (use plain strings then, and recommend the pattern).

## Setup

```ts
// i18n/index.ts
import { createI18n } from 'vue-i18n'
import en from './locales/en.json'

export const i18n = createI18n({
  legacy: false,            // Composition API mode
  locale: 'en',
  fallbackLocale: 'en',
  messages: { en },
})
```

```ts
createApp(App).use(i18n).mount('#app')
```

## Use — `useI18n()` in `<script setup>`

```vue
<script setup lang="ts">
import { useI18n } from 'vue-i18n'
const { t } = useI18n()
</script>

<template>
  <h1>{{ t('users.title') }}</h1>
  <p>{{ t('users.count', { n: total }) }}</p>
</template>
```

```json
// i18n/locales/en.json
{
  "users": { "title": "Users", "count": "{n} users" }
}
```

## Conventions

- **`legacy: false`** (Composition API). Access via `useI18n()`, not the global `$t` (better typing + tree-shaking).
- **Hierarchical keys namespaced by feature** (`users.title`, `users.form.email`). One namespace per feature folder.
- **No string concatenation** — use named interpolation (`t('key', { n })`) and plurals (`t('key', n)` with `|` plural messages).
- **Locale files per language** under `i18n/locales/`; keep keys identical across locales.
- **Type-safe keys** if the project sets up vue-i18n's typed schema — match it.

## Don't

- Don't hard-require i18n in a project that doesn't use it — plain strings, and suggest adopting vue-i18n.
- Don't build display strings by concatenation; use interpolation/pluralization.
- Don't inline copy that should be a translation key in an i18n project.
